# Use the IBX HTTP API

The **IBX API** is JSON over HTTPS at https://ibx.egeuysal.com. The API Reference tab is generated from the OpenAPI file in this docs project; this page explains auth, common payloads, and the owner-scoped workflow.

## Authenticate

The **Bearer header** carries an iak_ API key:

```bash
curl -sS https://ibx.egeuysal.com/api/todos \
  -H "Authorization: Bearer iak_your_key_here" \
  -H "Accept: application/json"
```

The **permission model** is method-based:

- **read** allows GET, HEAD, and OPTIONS.
- **write** allows POST, PATCH, and DELETE.
- **both** allows both classes.

Session cookies and Clerk sessions also work on the routes that allow them. Unsafe cookie-authenticated requests must include a same-origin Origin or Referer; a server-side Bearer request does not need that browser CSRF signal.

## Check auth state

The **session endpoint** always returns JSON. An unauthenticated caller receives authenticated false instead of a 401:

```bash
curl -sS https://ibx.egeuysal.com/api/session \
  -H "Authorization: Bearer iak_your_key_here"
```

The response includes **authType**, the API-key permission when applicable, and a session expiry when the legacy password session is active.

## Generate todos from a thought

The **generation endpoint** accepts one normalized text input and optional scheduling preferences:

```bash
curl -sS -X POST https://ibx.egeuysal.com/api/todos/generate \
  -H "Authorization: Bearer iak_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Finish the landing page and email two leads",
    "preferences": {
      "autoSchedule": true,
      "includeRelevantLinks": true,
      "requireTaskDescriptions": true,
      "availabilityNotes": "No meetings after 4pm",
      "executionSpeedMultiplier": 4
    }
  }'
```

The **generation result** includes runId, created, updated, deleted, mode, message, and droppedMutationOps. AI reconciliation can update or remove matching open todos, so treat generation as a mutation rather than a read.

The **input limit** is 8,000 characters. The endpoint returns 400 for empty input and 500 when the AI or Convex mutation fails. Retrying is bounded inside the server for transient mutations; clients should avoid duplicate retries after an unknown response.

## Read and edit todos

The **todo list** returns all owner-scoped todos:

```bash
curl -sS "https://ibx.egeuysal.com/api/todos?today=2026-08-21" \
  -H "Authorization: Bearer iak_your_key_here"
```

The **today query** asks the server to enforce due-date rescheduling before returning the list. Each todo includes status, schedule fields, priority, recurrence, source, and a Bri publication URL when one exists.

Create a **manual todo** with POST /api/todos:

```bash
curl -sS -X POST https://ibx.egeuysal.com/api/todos \
  -H "Authorization: Bearer iak_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Email Pat",
    "notes": "Send a concise follow-up",
    "dueDate": "2026-08-22",
    "estimatedHours": 0.5,
    "priority": 1,
    "recurrence": "none"
  }'
```

Update a **todo by stable ID**:

```bash
curl -sS -X PATCH https://ibx.egeuysal.com/api/todos/<todo-id> \
  -H "Authorization: Bearer iak_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"status":"done"}'
```

The **PATCH route** can change status, title, plain notes, rich notes, dueDate, estimatedHours, timeBlockStart, recurrence, and priority. DELETE permanently removes the owner-scoped todo.

## Sync thoughts

The **thought endpoints** support clients that keep a local capture log:

```text
GET  /api/thoughts
POST /api/thoughts/sync
GET  /api/thoughts/<external-id>/todos
POST /api/thoughts/<external-id>/todos
POST /api/thoughts/<external-id>/generate
```

The **externalId** is the client-owned reconciliation key. Sync accepts pending, processing, done, and failed statuses; invalid entries are ignored and an empty valid batch returns an empty thoughts array.

## Upload and manage attachments

**Files** belong to a todo, thought, or the owner's Files library. Uploading, saving metadata, changing visibility, and deleting require write permission; listing and resolving files require read permission. Cookie-authenticated writes also require the same-origin CSRF signal described above. File bytes are stored in private Cloudflare R2; Convex stores ownership and metadata.

1. **Request an upload URL** with authenticated `POST /api/attachments/upload-url`, sending `parentKind`, `parentId`, `fileName`, `contentType`, and `size` as JSON. Use `parentKind: "file"` and `parentId: "library"` for the Files library. The response contains a short-lived R2 `uploadUrl`, `method: "PUT"`, required `headers`, an opaque `uploadToken`, and `limits`.
2. **Upload raw bytes** with `PUT` to the returned URL using the returned headers. Do not use multipart form data or send your IBX Bearer key/session cookies to R2.
3. **Complete the upload** with authenticated `POST /api/attachments` and `{ "uploadToken": "<returned token>" }`.

```bash
curl -sS -X POST https://ibx.egeuysal.com/api/attachments/upload-url \
  -H "Authorization: Bearer iak_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"parentKind":"file","parentId":"library","fileName":"demo.mp3","contentType":"audio/mpeg","size":12345}'
```

For step 2, set `UPLOAD_URL` and `UPLOAD_TOKEN` from step 1:

```bash
curl -sS -X PUT "$UPLOAD_URL" \
  -H "Content-Type: audio/mpeg" \
  --data-binary @./demo.mp3
curl -sS -X POST https://ibx.egeuysal.com/api/attachments \
  -H "Authorization: Bearer iak_your_key_here" \
  -H "Content-Type: application/json" \
  -d "{\"uploadToken\":\"$UPLOAD_TOKEN\"}"
```

The **200 completion response** includes `{ ok: true, id, fileName, url, publicUrl, visibility }`. For `parentKind: "todo"`, use the full todo ID; for `"thought"`, use its externalId. The parent must exist and belong to the authenticated owner. Invalid metadata, a missing parent, an expired ticket, or uploaded bytes that do not match the signed size/type returns **400**.

The **size limit** is 1 byte through **30 MiB (31,457,280 bytes)**. Allowed MIME types are `application/pdf`; `image/gif`, `image/jpeg`, `image/png`, `image/webp`; `text/markdown`, `text/plain`; `audio/mpeg`, `audio/mp3`, `audio/mp4`, `audio/wav`, `audio/x-wav`, `audio/ogg`, `audio/webm`; and `video/mp4`, `video/webm`, `video/quicktime`, `video/ogg`, `video/x-m4v`. Check the returned limits before uploading.

**Filenames** are normalized to lowercase URL-safe names, up to 180 characters. Duplicate names within an owner receive suffixes such as `demo-2.mp3`; deleted names remain reserved so an old link cannot point at a new upload. Use the returned fileName and URL, not a URL built from the original filename. If names through `-100` are taken, rename the file.

**List attachments** through the owner-scoped API:

```text
GET    /api/attachments?parentKind=todo&parentId=<todo-id>
GET    /api/attachments?parentKind=thought&parentId=<external-id>
GET    /api/attachments?all=true
```

The **list response** is `{ attachments: [...] }`, newest first. Each item includes id, parentKind, parentId, fileName, contentType, size, status, timestamps, visibility, url, and nullable publicUrl. Per-parent queries inspect at most 50 records; `all=true` inspects at most 100 across the owner, ignoring parent filters.

### Files library and profiles

`GET /api/files?cursor=<cursor>` returns the signed-in owner's files in pages of 50 and their folders. Create a root folder with `POST /api/files` and `{ "name": "Projects" }`; pass `parentFolderId` to create a nested folder (up to 200 folders per account and 20 levels deep). `PATCH /api/files/<id>` with `{ "folderId": "<folder-id>" }` moves any owned attachment, including todo and thought attachments, into a folder; use `{ "folderId": null }` to move it to My Drive. The same endpoint accepts `{ "visibility": "public" | "private" }` to change sharing. `DELETE /api/files/<id>` removes an owned file. Files are **private by default**. Public file downloads are available without authentication at `/{username}/{folder-slug}/.../{fileName}`. Moving a file updates its public link path, while its previous flat URL remains a compatibility link. Profiles at `/{username}` show only public files and public Bri publications. Anyone with a public URL can download it; noindex is not access control. Deletion returns `{ ok: true }` or **404** and deletes stored bytes. Making a legacy Convex-backed file private first copies and verifies it in R2, then removes its old public-storage reference.

### Resolve and share files

**Authenticated resolution** uses `GET /api/attachments/<attachment-id>/url`, returning a safe app URL and nullable `publicUrl`; it never returns an R2 credential or signed storage URL. `GET /api/attachments/<attachment-id>/file` streams bytes through IBX with **200** and `Cache-Control: private, no-store`. Both routes require read permission and ownership; unavailable IDs return **404** and storage failures return **502**.

**Public downloads** use `GET /{username}/{folder-slug}/.../{fileName}` without authentication. The route streams bytes inline with `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, wildcard CORS, and `X-Robots-Tag: noindex, nofollow`. It forwards `Range` and `If-Range` and preserves storage's **200**, **206**, or **416** response and range headers, supporting audio/video seeking. The legacy `/{username}/{fileName}` form continues to resolve. Invalid paths and private/missing files return 404; storage failures return 502.

<Aside>
<Warning>
**Public links are not private storage.** Anyone with or able to guess a public username/file URL can download it without signing in; noindex is not access control. Notes and attachment management remain owner-scoped. Private files never appear on public profiles.
</Warning>
</Aside>

## Errors

An **error response** normally contains an error string. The most useful statuses are:

- **400** invalid input, date, recurrence, priority, or resource ID.
- **401** missing or invalid session, Clerk token, or API key.
- **403** CSRF/origin rejection or a permission mismatch.
- **404** a requested todo or thought does not exist.
- **429** password login rate limiting.
- **500** AI, Convex, attachment, or internal server failure.

The **API is owner-scoped**: a valid credential can only read and mutate the records associated with its owner key. Keep raw keys out of URLs, logs, browser bundles, and public Shortcut files.
