# Use the IBX CLI

The **ibx CLI** is a TypeScript terminal client with browser authentication, API-key fallback, bounded retries, structured stderr logs, and stable exit codes.

## Authenticate

The **interactive login** opens a browser for Clerk approval:

```bash
ibx login
ibx auth status
ibx whoami
```

Use an **API key** for CI or headless automation:

```bash
ibx login --api-key iak_your_key_here --url https://ibx.egeuysal.com
```

The **credential store** prefers macOS Keychain, Windows Credential Manager, or Linux Secret Service. When no OS store is available, the CLI uses a local config file with 0600 permissions and prints a warning.

## Capture and list

The **capture command** sends raw text for generation:

```bash
ibx add "finish the landing page and email two leads" --auto-schedule
ibx todos list --view today
ibx todos list --view upcoming
ibx td
```

The **short aliases** are ibx n for capture, ibx t l for list, and ibx td for completed tasks in the America/Chicago timezone unless IBX_TIMEZONE overrides it.

## Manage a todo

The **manual todo command** creates a task without AI:

```bash
ibx todos add "email Pat" --notes "Send a concise follow-up" --due 2026-08-22 --priority 1
ibx todos done --id <todoId-or-prefix>
ibx todos set --id <todoId-or-prefix> --recurrence weekly
ibx todos delete --id <todoId-or-prefix>
```

The **prefix lookup** is convenient for humans, but stable full IDs are safer in scripts. Add --json to commands that support machine-readable output.

## Publish and attach

The **Bri integration** can publish a todo or thought when IBX has a configured Bri connection:

```bash
ibx publish <todoId-or-prefix>
ibx publish --private <todoId-or-prefix>
ibx publish unpublish <todoId-or-prefix>
ibx attach ./design.png
ibx attach ./design.png --directory /content/2026/10/25 --public
ibx mkdir /content/2026/10/25
ibx attach <todoId-or-prefix> ./design.png
ibx attach list <todoId-or-prefix>
ibx attach list --all
ibx files tree
ibx files upload ./design.png --folder <folderId>
ibx files mkdir Projects
ibx files rename <itemId> "new name.png"
ibx files move <fileId> <folderId>
ibx files public <fileId>
ibx files private <fileId>
ibx files delete <fileId>
```

The **publication URL** is stored with the source record and appears as briUrl in todo API responses. A missing Bri connection is a configuration issue, not a reason to retry the same publish indefinitely.

The **Files commands** browse and manage the same library as the web app. `ibx files tree` prints folders and files; add `--json` for the owner-scoped `/api/files/tree` response. Uploads are private unless `--public` is supplied, and Files library uploads allow up to **500 MiB**. Rename a file or folder by ID; duplicate file names in the same directory receive a suffix. The `move` target can be `root` to return a file to drive.

**File uploads** read a local file: `ibx attach <file>` uploads privately to Files (up to **500 MiB**); use `--directory /path` to create nested folders and place it there, and `--public` to enable its public URL. `ibx mkdir /path` creates a directory tree. `ibx attach <todoId> <file>` remains available for private todo attachments, which are limited to **30 MiB (31,457,280 bytes)**. `ibx attach list <todoId>` lists a todo's attachments; `ibx attach list --all` lists attachments across your owner account (up to 100 records before deleted entries are filtered). Each prints file URLs; add `--json` for structured output. Supported types include PDF, GIF/JPEG/PNG/WebP, Markdown/plain text, MP3/M4A/WAV/OGG, and MP4/M4V/MOV/WebM/OGV. Duplicate names receive suffixes such as `design-2.png`.

### In-app terminal

The **browser terminal** uses a file chooser instead of a shell path:

```text
attach <number|id>
attach <number|id> --directory /content/YYYY/MM/DD
attach --directory /content/YYYY/MM/DD
mkdir /content/YYYY/MM/DD
attach list <number|id>
```

**`attach`** targets a todo by its displayed number or ID, opens the browser file chooser, and prints the public URL after upload. **`attach list`** lists that todo's attachments. Browsers cannot read arbitrary shell paths; use the installed `ibx` CLI when you need `./file.mp3` uploads.

<Warning>
**Attachment links are public** when your account has a username: anyone with or able to guess the URL can download without signing in. Notes and attachment writes remain owner-scoped. Without a username, create/list URLs use an authenticated file route. See [attachment API details](../reference/http-api.mdx#upload-and-manage-attachments).
</Warning>

## Reliability and exit codes

- **2** means validation or input error.
- **3** means authentication error.
- **4** means network or timeout error.
- **5** means server error.
- **6** means the target was not found.
- **7** means the target was ambiguous or conflicted.
- **8** means rate limiting.

The **update check** runs once per day against ibx-version.json; set IBX_DISABLE_UPDATE_CHECK=1 in isolated automation. Use ibx self-update to fetch the latest GitHub release asset.
